## 0. 链路一图看完

```
天气报告（24h 逐时 + 日级）
  → WeatherContext（统一整点事实，缺逐时时用合成曲线）
  → 人群解算（中性温度）+ 活动解算（代谢/自生风/日晒/雨暴露）
  → 偏好解算（风格/呈现/版型/色彩/场合/暴露习惯/出汗/反馈 → 软排序加成与保暖/透气/正式度偏差）
  → 通勤暴露窗口（planExposure：穿衣防雨与带伞共用同一组事实）
  → 逐时热状态：全天 24 个整点各算 作用温度 与 所需 clo（**不封顶**）
  → 设计时刻：全天所需 clo 最高的那一小时（衣物清单由它定）
  → 安全预警（先算，只上调需求，永不下调）
  → 六维需求向量（展示维 0-100 会饱和；选衣读的是**未封顶的保暖缺口**）
  → 层槽位（贴身×2 必有 + 保暖 0~2 + 防护 0~1，上限 5；严寒即使无风无雨也强制外层）
  → 每槽候选（反季硬过滤 → 拟合分前 6 + 最厚 2；偏好命中另有池内软加分）
  → **整套联合搜索**（beam 宽度 64 + 搜后精修 + 分数接近时复用上一套；逐槽取最优但不合格必须登记，不静默兜底）
  → 有效 clo（同角色叠加打 85 折；风挡不足再 ×0.85）+ 分项满分制评分（保暖 25／防护 20／活动 15／风格 18／协调 10／可脱 5／偏好 4／多样性 3，合计 100）
  → 覆盖判定 coverage（够/勉强/不够/未知）+ 雨具两件事 rainPlan（穿与带同源）
  → 此刻穿哪几层（按当前作用温度决定 active）+ 时段/时间线 + 配饰 +（带伞判定同源）
```

三条贯穿全链的口径，先记住，否则后面的表看不懂：

1. **衣物清单按"全天最坏时刻"定，"此刻穿几层"按"现在"定。** 同一天里从早到晚，推荐清单不变，变的只是哪些层穿着（第 2.10 节实测）。
2. **上装与下装放在同一卷里联合比较**：反季件在准入阶段就被挡掉、下装过薄会被扣分、组装用整套得分搜索——不再各自独立取第一名（第 2.6~2.7 节）。
3. **需求只会上调不会下调**：安全预警用 `max` 合并；"穿得够不够"由独立的覆盖判定说话，与推荐分数分开（第 2.12 节）。

## 2. 逐步拆解：每个判定点与实测

### 2.1 作用温度（每个整点）

```
作用温度 = 气温 + 辐射增益 − 风寒 + 湿度负载
```

| 项 | 规则 | 阈值/系数 |
| --- | --- | --- |
| 辐射增益 | 只在 7–18 点算；= 辐射 W/m² × 0.006，**封顶 5℃** | 晴天 600 W/m² → +3.6℃ |
| 风寒 | 只在气温 ≤10℃ 且风速 ≥4.8 km/h 时算；标准风寒公式取"降温量" | 风 >10℃ 一律不计 |
| 湿度负载 | 只在气温 ≥26℃ 时算；每高出基准 40%RH 的 10% → +0.6℃ | 90%RH 时 +3.0℃ |
| 有效风 | 环境风速 + 活动自生风 | 骑行 +4.0 m/s |

要点：**湿度只在高温侧起作用**（低温时不看湿度，避免把"湿冷"误算成"更冷"），所以低温湿度差异不影响作用温度，只影响透气需求。

### 2.2 所需 clo 与设计时刻

```
所需 clo = (中性温度 − 作用温度) / 12      ≤0 记 0，**不封顶**
```

**每 1 clo 对应 12℃ 温差**（旧版是 6.5，会把 0℃ 静坐需求推到 3.4 clo，远超任何合理着装；改为 12 后 0℃ ≈ 1.8 clo、−10℃ ≈ 2.7 clo，与 ISO 9920 的组合热阻量级一致）。

设计时刻 = 全天所需 clo 最高的那一小时（实测里就是凌晨最低温那小时，如均温 −22℃ 那天是凌晨 3 点、−27℃）。**衣物清单由它决定**。

选衣用的保暖缺口 = 设计时刻所需 clo − 代谢抵消，同样不封顶：

| 均温（日内 ±5℃） | 设计时刻 | 设计时刻所需 clo | 选衣用缺口（扣代谢后） |
| --- | --- | --- | --- |
| −22℃ | 3 时 −27℃ | 4.77 | 4.47 |
| −16℃ | 3 时 −21℃ | 4.18 | 3.88 |
| −8℃ | 3 时 −13℃ | 3.38 | 3.08 |
| 0℃ | 3 时 −5℃ | 2.59 | 2.29 |
| 8℃ | 3 时 3℃ | 1.80 | 1.50 |
| 16℃ | 3 时 11℃ | 0.92 | 0.62 |
| 20℃ | 3 时 15℃ | 0.58 | 0.28 |

（此为 C3 行内实测读数；缺口从 −22℃ 到 20℃ 单调下降，低温侧不再有"所有天共用同一个数"的饱和。）

### 2.3 安全预警（先算，强制抬需求）

| 触发 | WATCH | DANGER | 强制需求 |
| --- | --- | --- | --- |
| 白天最高温 | ≥33℃ | ≥35℃ | DANGER：透气 ≥80、遮阳 ≥70、保暖 0；WATCH：遮阳 ≥40 |
| 凌晨最低温 | ≤−5℃ | ≤−10℃ | 保暖 ≥75 / ≥95 |
| 全天最大风 | ≥10 m/s | ≥15 m/s | 防风 ≥50 / ≥90 |
| 全天雨量 | ≥4 mm | ≥8 mm | 防雨 ≥60 / ≥95 |
| 老人/儿童 + 最高温 ≥33℃ | — | — | 透气 ≥60 |

实测：37℃ 晴天 → DANGER，需求 = 透100/晒80，衣物 速干背心+沙滩裤+防晒衣，配饰 墨镜/遮阳帽/防晒霜/备用贴身衣。

### 2.4 六维需求向量（各维取全天最坏）

| 维度 | 驱动量 | 0→100 的区间 | 修正 |
| --- | --- | --- | --- |
| 保暖 WARMTH | 全天最大所需 clo（展示用） | 0.4 → 2.0 | −代谢抵消×15 |
| 防风 WIND | 全天最大有效风（环境+自生） | 4 → 12 m/s | — |
| 防雨 RAIN | max(降水概率 30→85，雨量 0.5→4 mm/h) | — | ×雨暴露系数 ×暴露习惯（0.6/1/1.2）；**通勤窗口有雨再抬到 40**（见第 2.13 节） |
| 透气 BREATHABILITY | 作用温度 | 25 → 33℃ | 湿度>70% +15；MET≥3.5 至少 45 |
| 遮阳 SOLAR | UV 指数 | 3 → 8 | ×日晒暴露系数 ×人群日晒敏感 |
| 可脱卸 REMOVABLE | 昼夜温差 | 8 → 16℃ | — |

**展示维保暖有饱和点**：所需 clo ≥ 2.0（作用温度 ≤ −2℃ 附近）就显示 96 分上下。实测静风扫描（F1）：−22℃ 到 6℃ 的展示保暖都顶在 96，8℃ 降到 83、10℃ 降到 71、12℃ 降到 58，**但这不再意味着同一套衣服**——选衣读的是第 2.2 节那张不封顶缺口表：−22℃ 缺 4.47 clo（库都不够，报 insufficient）、0℃ 缺 2.29、6℃ 缺 1.70，实测组合与覆盖判定逐档不同（第 4.1 节）。展示维的饱和只影响数字观感，不影响任何选衣决策。

### 2.6 每槽候选怎么挑（准入 + 拟合评分）

先按 `层角色 + 品类` 分池（保暖槽在严寒时并入厚外套），再硬过滤：

1. **clo ≥ 槽位下限**；
2. 要求防水则 `water ≥ 0.85`；要求防风则 `wind ≥ 0.6`；要求遮阳则 `solar ≥ 0.8`；
3. **反季准入**：设计时刻超出这件衣服的舒适窗 **±6℃** 即淘汰（"季节不对"不是"差一点"）。**防护层槽豁免**——雨衣/防风壳在盛夏深冬都要可达。

过滤后按拟合分排序取 **前 6 件**，再补 **最厚的 2 件合格件**（贴合排序天然偏好"差值最小"，厚度选项必须留在桌上给联合评分）：

| 项 | 公式 | 说明 |
| --- | --- | --- |
| 保暖层就近 | `30 − min(30, |clo − (槽下限+0.1)| × 40)` | 越接近目标越高分 |
| 贴身层透气 | `透气 × 20 × (0.4 + 透气需求/100 × 0.6)` | 冷季权重 0.4，热季 1.0 |
| 贴身层目标 clo | 上装 `0.05 + 缺口刻度×0.3`；下装 `0.04 + 缺口刻度×0.26`，再 ×(0.6+缺口刻度) | 缺口刻度 = min(1, 缺口/3.0)；贴身只承担一小份保暖 |
| 防护层侧重 | 防水壳 `water×30`、防风壳 `wind×25`、遮阳 `solar×35`，另加 `透气×10` | 按槽位要求叠加 |
| 轻量 | `(1 − 克重/1500) × 15` | 越轻越好 |
| 可脱卸 | `可脱卸需求 × 0.15`（仅可脱单品） | 温差大时偏外套 |
| 舒适窗 | 盖得住设计时刻 ±2℃ 时 +5 | — |
| 偏好加成（第四步） | 风格命中 +6 / 呈现命中 +4 / 版型命中 +3 / 色彩命中 +3 | 仅显式设置时生效；让合适件进得了前 6 池，默认设置下无加分 |

**合格池为空时的兜底**：退回该角色+品类的原始池，按"离设计时刻最近的件"排序取前 6——让极寒场景兜底的是最接近的一件（发热保暖裤），而不是拟合分恰好高的裙装或短打。这条有回归测试（S2-5：−24℃ 下 BASE/BOTTOM 候选首位是全库离设计时刻最近的件）。

### 2.7 组装：整套联合搜索（beam 64 + 搜后精修 + 稳定性复用）

不再"逐槽取第一名然后祈祷"。组装是**在所有槽位的候选组合上做 beam 搜索**（`beamWidth: 64`），每个中间组合按整卷得分剪枝；最优路径再走 2 轮**搜后精修**（逐槽单件替换爬山，得分更高才采用）。同一件衣服不会在一套里出现两次。

每一步的硬条件检查（`slotHardSatisfied`，比准入更严）：`water ≥ 0.9`（防水槽）、`wind ≥ 0.7`（防风槽）、`solar ≥ 0.8`（遮阳槽）、`clo ≥ 槽下限`、**且过反季准入**。某个槽位没有任何候选过得了硬条件时：

- 保留"尽力而为"的一件给界面展示，但整卷登记 `RELAXED_<角色>`；
- 候选池为空则登记 `NO_CANDIDATE_<角色>_<品类>`，不产生凭空衣物；
- 覆盖判定读到任何 relaxed 就直接判 `insufficient`，**不把不合格的组装冒充合格推荐**（第 2.12 节）。

**为什么宽度是 64**（E1 实测）：北方寒潮场景下宽度 32→57.1 分/有效 2.30 clo（偏薄的组合）、48→62.1/3.76、**64 起 62.8/3.79 与全枚举 20000 同分**——宽度 32 有可见剪枝代价，64 已把产品场景拉到全枚举水平。构造场景（T6w）各宽度 32:82.9 / 64:82.8 / 256:82.6 / 20000:83.1，极差 ≤0.5 分且互有高低（不同宽度的路径经精修收敛到不同局部最优）。S5-4 把 `beamWidth` 改回 32 会立刻变红。

**搜后精修确实在补分**（B2a/B2d 实测）：T6w 关掉精修 80.8 → 打开 82.8，差 2.0 分。S2-6 三个判别场景在宽度 1 / 64 / 20000 下分别 76.3 / 77.3 / 82.6，**三方完全相等**——这些场景里精修把 64 与全枚举拉到同一水平；验证句也从旧版"严格优于贪心"改成**"产品配置（64 + 精修）不劣于全枚举（20000）− 1 分"**。

**搜索质量的实测对照**（C13/C8）：北方寒潮产品 62.8 = 全枚举 62.8（同套件）；T6w 产品 82.8 vs 全枚举 83.1（差 0.3）；C8 的 6℃ 与 −20℃ 近似场景 beam 与全枚举同分（79.3=79.3、64.1=64.1）、贪心低一档（78.6 / 63.4），雨天场景 83.5 三方全等。beam 不是严格最优，但产品场景偏差已收敛到 ≤0.4%，第 5.2 节遗留 3 只剩"构造场景差 0.3 分"。

**复用稳定性（S5-6 / S5-8）**：上一天有输出（`previousItemIds`）时，新候选整套若每个槽仍过硬条件、且两套的"合身分"（**两边都不计多样性分**，`fitPrefs` 口径）差 ≤ `reuseMargin = 3 + reuseBonus`（`reuseBonus` = 「很合适」条数 ×1 分，帽 +2）就直接沿用上一套，输出里标 `reusedPrevious`。实测：12℃→13℃ 沿用（基础分 79.7 vs 81.5，差 1.8）；12℃→−5℃ 换（缺口与硬条件都变了）；晴→雨必换壳（硬条件优先级更高）。容差阶梯（S5-8，按基础分差，呈现准入修复后重标）：6℃→10℃ 差 ∈ (3,4]——裸比对整套换、一条「很合适」（容差 4）就沿用；12℃→15℃ 差 ∈ (4,5]——一条不够、两条（容差 5）沿用、五条仍封顶 5；5℃→8℃ 已收敛 ≤3（无反馈直接沿用，稳定性正例）；「闷」×3 不放宽，同场景仍整套换。

### 2.8 有效 clo（叠穿不等于相加）

- **打折按"角色"发生**：同一角色里排第二的那件只算 `clo × 0.85`。贴身下装与贴身上装同属 BASE 角色，所以第二条 BASE 同样被打折——这是保守估计（上下装实际是并排覆盖），代码注释与实现现已一致。
- **外层风挡 < 0.8 → 整套再乘 0.85**（风穿透）；**没有外层时同样吃这个 0.85**，即"不穿壳"在数值上被视为漏风。

实测 −22℃ 那套（发热保暖内衣 0.36 + 发热保暖裤 0.32 + 棉服 1.0 + 羽绒服 1.2 + 派克服 1.15）：名义 `0.36 + 0.32×0.85 + 1.0 + 1.2×0.85 + 1.15 = 3.80`，外层派克服风挡 0.75 < 0.8 再 ×0.85 → **有效 3.23 clo**。

### 2.9 评分（匹配度分，不是"穿得对不对"）

第四步起改为**分项满分制**（方案 §7.3），第五步补齐到八项：保暖 25 / 天气防护 20 / 活动舒适 15 / 风格场合 18 / 整套协调 10 / 可脱卸 5 / 用户偏好 4 / **多样性 3，合计 100**。`dayScore` = 八项之和（0–100），`scoreBreakdown` 输出逐项得分给界面分数卡。硬过滤与安全判定不读分数——分数只决定"合格候选里谁排前面"；复用稳定性比对读的是剔除多样性后的"合身分"（第 2.7 节）。

| 分项 | 满分 | 怎么算 |
| --- | --- | --- |
| 保暖 | 25 | `缺口 = requiredClo（含反馈偏置）− 有效clo`；欠保暖每 1 clo 扣 22.5 分（穿少了会冷，罚得重）；略微过暖每 1 clo 扣 6.25 分、**封顶 7.5 分**（穿多了只是沉） |
| 天气防护 | 20 | 风/水/晒属性按需求加权后归一，**只有当天真有该维需求（>0）的维度才带权重入场**（权重 = 该维需求/100 + 0.15）；三维全为 0 → 中性 16 分（20×0.8），防护属性不参与排名（S5-1 水项条件化：纯风天不再让"最防水的壳"白拿防水分） |
| 活动舒适 | 15 | 透气 70% + 轻量 30%；透气权重 = 0.4 + 0.6 ×（透气需求/100 + 闷反馈偏置）；重量预算 2500g 线性衰减 |
| 风格场合 | 18 | 只统计用户显式设置的子项：风格多选（权重 0.55）与穿着场合正式度（权重 0.45 + 不符合场合反馈偏置）；未设置取中性 0.8 档 = 14.4 分，不产生排序信号 |
| 整套协调 | 10 | 设计时刻低于 12℃ 起折算下装应承担的保暖分额 `(12 − 设计时刻) × 0.03 clo`（上限 0.32 clo，约一件加绒长裤），下装不足每缺 1 clo 扣 6 分；整套 ≥3 个非中性色组再扣 2 分（S2-4 验证：0℃ 薄下装组严格更低分，24℃ 两组相等） |
| 可脱卸 | 5 | 可脱件数 2 件即取满（温差场景够用） |
| 用户偏好 | 4 | 色彩 0.4 / 版型 0.3 / 呈现 0.3 三个子项各自命中率加权；未设置取中性 0.8 档 = 3.2 分，不产生排序信号 |
| 多样性 | 3 | 与上一套 `previousItemIds` 的"新鲜件占比"×3：全换=3、全同=0；没有上一套记录时取满 3（S5-5，第五步（二）） |

**反馈闭环**（方案 §6.1）：每条反馈只小步调整、有上限、可撤销——"太冷/太热"每步改保暖目标 ±0.1 clo（帽 ±0.3），"闷"每步抬透气权重 0.1（帽 0.3），"不符合场合"每步加大正式度权重 0.1（帽 0.3），"正合适"每条放宽复用容差 1 分（帽 2 分），不直接改分；撤销 = 删最后一批（`revokeLastFeedback`；一次「偏热 / 闷」点击同刻记两条，一起撤）。反馈不动安全阈值与天气事实。

**分数分布实测**（C1 阶梯）：−22℃ 47.4 分（扫到的最低）；0℃ 77.5；8℃ 79.3；26℃ 与 30~32℃ 89.5（最高）；28℃ 例外低一档（79.5，WATCH 档）——全带 47.4~89.5。极寒低分现在表达的是"缺口真实存在"，不再是旧版"目标固定 1.0 clo"的口径副作用。但**它依然只是匹配度，不是安全等级、也不是推荐可信度**——够不够穿由覆盖判定（第 2.12 节）与安全等级分别回答。

### 2.10 此刻穿哪几层

第五步（一）起，"此刻穿着"与时间线统一成**同一条逐时穿脱序列**（`buildWearingSeries`）——时间线就是相邻整点的状态差（最多 6 条事件），两处天然一致。规则：

| 层 | 规则 |
| --- | --- |
| 贴身层 | 始终穿着 |
| 保暖层 | 脱掉后剩余有效 clo ≥ 该小时所需 clo + 0.15 时脱下；低于所需 clo 时穿回（滞回防抖）；0 时按事实直接判，不把"半夜换装"带进时间线 |
| 防护层 | 降水时段必穿（安全侧不设滞回）；无雨时温度 ≤12℃ 穿、>14℃ 才脱（滞回带 2℃） |

实测三条整日时间线（C7；字母：B 贴身 / I 保暖 / P 防护，数字为整点区间；事件 = 相邻状态差）：

- **秋日昼夜 6~24℃（均温 15）**：0–8 时 `BI`，9–21 时只剩 `B`（白天升温脱掉中层），22–23 时回到 `BI`。事件：09:00 `REMOVE 充绒马甲`、22:00 `ADD 充绒马甲`——与逐时序列逐点一致。
- **春雨 5~14℃、8 点与 18 点有雨**：0–9 时 `BIP`，10–19 时 `BP`（中午脱的是保暖层，雨壳留着），20–23 时回到 `BIP`。事件：10:00 `REMOVE 抓绒衣`、20:00 `ADD 抓绒衣`——一致。
- **冬晴 −6~4℃**：0–11 时 `BIP`，12–17 时 `BP`，18–23 时回到 `BIP`。事件：12:00 `REMOVE 充绒马甲`、18:00 `ADD 充绒马甲`——一致。

| --- | --- |
| 围巾 | 全天最低 ≤ 4℃ |
| 手套 | ≤ −2℃ |

### 2.12 覆盖判定 coverage（衣物库够不够用）

输出字段：`status / requiredClo / availableClo / capacityClo / deficitClo / catalogDeficitClo / confidence / unmetNeeds`。判据读的需求含反馈保暖偏置（"太冷"反馈会同步抬高 `requiredClo`，覆盖口径不脱节）。四态判据（按序）：

| 判定 | 条件 | 含义 |
| --- | --- | --- |
| `insufficient` | 有槽位被放宽（RELAXED_*）；或 库容量缺口 > min(0.4 clo, 需求×0.4) | 不是"差一点"，是这套/这库真的不够 |
| `unknown` | 无逐时预报（且未被上面捕获） | 数据不够，不敢下结论；置信度 0.4 |
| `marginal` | 这套比需求薄 > 0.05 clo；或 需求 ≥0.3 且余量 < 0.2 clo | 勉强够，没有余量 |
| `adequate` | 其余 | 够用 |

`capacityClo` 是"同样槽位结构下，库里最多能凑到多少"（每槽贪心取最厚、不重复用件）——它把"这套偏薄（deficitClo）"与"库里根本没有（catalogDeficitClo）"分开，两者对用户的说法不同。

实测覆盖带（C1 温度阶梯 + C12 冷侧重扫，日内 ±5℃）：**−20℃ 及以下 insufficient**——读到的全是库容量缺口（catalogDeficit：−20 缺 0.44、−21 0.54、−22 1.64、−23 1.74、−24 2.84 clo），−24 还叠加两个保暖槽无候选（`NO_CANDIDATE_INSULATION_TOP`）与硬槽放宽；**−19~−16℃ marginal**（这套比需求薄 0.38→0.09，从"差一点"滑向"刚好"）；**−15~+2℃ 的"刚好够"带 marginal**（缺口 0~0.05 clo；−5℃ 恰过线报 adequate）；4℃ adequate；**6~18℃ marginal**（18℃ 薄 0.11）；20℃ 以上 adequate。

旧版 −10/−12℃ 的 `RELAXED_BASE` 已消失：当时发热保暖裤舒适窗下界 −8℃，离 −15℃ 设计时刻超过 ±6℃ 反季容差，贴身下装槽没有一件过得了硬条件；第五步（一）把该窗下界改到 −28℃ 后，−12℃ 起该槽不再被放宽（S5-2 锁定）。

### 2.13 雨具两件事：rainPlan（穿与带分开、同源）

`rainPlan` 把"带不带"与"穿不穿"分开给结论，但两条判定读同一组通勤暴露事实（`exposure.ts` 是唯一来源）：

| 字段 | 含义 |
| --- | --- |
| `facts.commuteMaxLegChance / commuteMaxLegMmPerHour / dayRainMm / windMaxInCommuteMs` | 通勤窗口内最大降水概率 / 最大雨强 / 全天雨量 / 窗口内风速峰值 |
| `carry` | 携带结论（= umbrella.verdict，SKIP/BRING/RAINCOAT） |
| `wearShell` | 是否真的需要穿防水外壳/雨衣 |

判定线：窗口内"最大整点概率 ≥ 40%"或"最大雨强 ≥ 0.5 mm/h"或"全天雨量 ≥ 4 mm"记 wetInWindow；`wearShell = 带伞结论不是 SKIP 且 wetInWindow`。**不带伞的日子也不要求穿防水壳**——两条结论不会互相打脸。

配套修复：防雨需求有一条**通勤下限**——窗口内最大整点概率 ≥40% 时，防雨需求抬到至少 40（0-100 刻度）。"室内办公"只把雨暴露权重降为 0，不等于不经过户外。实测（F2 复核）：14℃、概率 70%、雨强 0.8 mm/h（全天 1.6 mm）时，**办公与步行都会给出防水外层**（硬壳冲锋衣）——办公的防雨需求恰好压在 40 的通勤地板上、步行 58，且办公整卷还要多一件抓绒衣保暖；旧版办公在这种天不给壳、而带伞判定照样让人带伞的矛盾已消除。

## 3. 服装目录（内置 45 件，用户不能添加）

clo 参照 ISO 9920 量级。属性：保暖 clo、防风/防水/透气/遮阳（0–1）、克重、能否脱卸、舒适温度窗。
三点目录口径：**舒适窗下界是"叠穿体系下的可穿下限"**（可被外层罩住），不是单穿舒适下界；**外壳等级 shellGrade 只是目录元数据**，当前引擎不读取它（引擎用 water/wind 数值判定）；**第四步起每件带五类软标签**（风格/正式度/呈现/版型/色彩，curated 估算，缺失按中性回退）——只参与软排序与分桶评分，不进硬过滤；唯一例外是呈现准入（`presentationAdmissible`）：呈现标签不含 UNISEX 的专属件（当前唯一：厚裙）须显式选中该呈现才进池，"不指定"只给通用件（S4-9）。

- **防水一列全部是 40%**：这是"通勤窗口概率 ≥40% → 防雨需求抬到 40 → 壳槽"的下限线统一作用，任何活动（含室内）只要窗口里有雨都会拿到防水外层（C11r 9 行全部给硬壳冲锋衣）。旧版"室内永不触发、只有雨量 ≥4mm 才有例外"的断档已不存在。
- 防风一列内部自洽：除室内三行外，触发时的**有效风**（环境 + 自生风）都落在 6.6~6.7 m/s，正是防风需求过 32 的分界（4→12 区间的 32% 处 = 6.56）。

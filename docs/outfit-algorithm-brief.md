## 0. 链路一图看完

```
天气报告（24h 逐时 + 日级）
  → WeatherContext（统一整点事实，缺逐时时用合成曲线）
  → 人群解算（中性温度）+ 活动解算（代谢/自生风/日晒/雨暴露）
  → 偏好解算（风格/呈现/版型/色彩/场合/暴露习惯/出汗/反馈 → 软排序加成与保暖/透气/正式度偏差）
  → 通勤暴露窗口（planExposure：穿衣防雨与带伞共用同一组事实）
  → 逐时热状态：全天 24 个整点各算 作用温度 与 所需 clo（**不封顶**）
  → 设计时刻：全天所需 clo 最高的那一小时（衣物清单由它定）
  → 安全预警（先算，只上调需求，永不下调）
  → 六维需求向量（展示维 0-100 会饱和；选衣读的是**未封顶的保暖缺口**）
  → 层槽位（贴身×2 必有 + 保暖 0~2 + 防护 0~1，上限 5；严寒即使无风无雨也强制外层）
  → 每槽候选（反季硬过滤 → 拟合分前 6 + 最厚 2；偏好命中另有池内软加分）
  → **整套联合搜索**（beam 宽度 32；逐槽取最优但不合格必须登记，不静默兜底）
  → 有效 clo（同角色叠加打 85 折；风挡不足再 ×0.85）+ 分项满分制评分（保暖 25／防护 20／活动 15／风格 18／协调 10／可脱 5／偏好 4）
  → 覆盖判定 coverage（够/勉强/不够/未知）+ 雨具两件事 rainPlan（穿与带同源）
  → 此刻穿哪几层（按当前作用温度决定 active）+ 时段/时间线 + 配饰 +（带伞判定同源）
```

三条贯穿全链的口径，先记住，否则后面的表看不懂：

1. **衣物清单按"全天最坏时刻"定，"此刻穿几层"按"现在"定。** 同一天里从早到晚，推荐清单不变，变的只是哪些层穿着（第 2.10 节实测）。
2. **上装与下装放在同一卷里联合比较**：反季件在准入阶段就被挡掉、下装过薄会被扣分、组装用整套得分搜索——不再各自独立取第一名（第 2.6~2.7 节）。
3. **需求只会上调不会下调**：安全预警用 `max` 合并；"穿得够不够"由独立的覆盖判定说话，与推荐分数分开（第 2.12 节）。

## 1. 输入侧：谁在影响结论

| 输入 | 取值 | 影响什么 |
| --- | --- | --- |
| 人群 | 儿童 / 成人 / 老人 | 中性温度偏移 +1.8 / 0 / +2.5℃；日晒敏感 1.3 / 1 / 1.1 倍；老人儿童额外"保守"（高温时抬透气需求） |
| 冷热体质 | 怕冷 / 正常 / 怕热 | 中性温度 +2.0 / 0 / −1.5℃ |
| 活动 | 9 种（下表，界面 9 种全部可选） | 代谢、自生风、日晒暴露、雨暴露、带伞暴露时长 |
| 风格 | 8 种可多选（日常/通勤/商务/运动/户外/街头/日系宽松/韩系清爽） | 候选择序软加分 + 风格分桶（缺省不产生排序信号） |
| 呈现 / 版型 / 色彩 | 呈现三选（男/女/中性）/ 版型三选（修身/常规/宽松）/ 色彩四选 | 偏好分桶与候选择序（缺省不产生排序信号） |
| 场合 | 6 种（日常/办公/校园/运动/户外/正式） | 风格分桶里的正式度贴合（日常为默认档，不产生信号） |
| 暴露习惯 | 室内为主 / 短时户外 / 长时户外 | 防雨需求权重 ×0.6 / ×1 / ×1.2（"通勤窗口有雨≥40%"的下限不受它影响） |
| 出汗 | 不易 / 一般 / 易 | 易出汗在透气需求 >30 时提前给"备用贴身衣"（理由码 `sweat-easy`） |
| 反馈历史 | 太冷/太热/闷/不符合场合/正合适（追加式、可撤销） | 保暖目标 ±0.1 clo 步进（±0.3 帽）、透气与正式度权重抬升；不动安全阈值 |
| 天气 | 逐时气温/湿度/风/降水概率/雨强/UV/云量/辐射 + 日级最低最高/雨量/概率/UV 峰值 | 全部 |
| 当前时刻 | 时钟 | 只影响"此刻穿哪几层"、时段划分、带伞哪一段还来得及 |

中性温度 = 22 + 人群偏移 + 体质偏移，**实际范围 20.5 ~ 26.5℃**（怕热成人 vs 怕冷老人差 6℃，折算约 0.92 clo 保暖差）。

活动解算表（`ACTIVITY`，全部为可配参数）：

| 活动 | 代谢 MET | 自生风 m/s | 日晒暴露 | 雨暴露 | 代谢抵消 clo | 高强度必透气 |
| --- | --- | --- | --- | --- | --- | --- |
| 居家 | 1.0 | 0 | 0.2 | **0** | 0 | 否 |
| 办公 | 1.1 | 0 | 0.1 | **0** | 0.025 | 否 |
| 上课 | 1.2 | 0 | 0.2 | **0** | 0.05 | 否 |
| 步行 | 2.2 | 0.6 | 0.8 | 0.8 | 0.30 | 否 |
| 骑行 | 4.2 | 4.0 | 1.0 | 1.0 | 0.80 | 是 |
| 跑步 | 6.5 | 3.0 | 1.0 | 0.9 | 1.375 | 是 |
| 户外工作 | 3.5 | 0.4 | 1.0 | 1.0 | 0.625 | 是 |
| 户外休闲 | 2.4 | 0.6 | 0.9 | 0.9 | 0.35 | 否 |
| 开车 | 1.4 | 0.2 | 0.5 | 0.6 | 0.10 | 否 |

**代谢抵消 clo = (MET − 1) / 4**。它作用在两处：① 从"最冷整点所需 clo"里扣掉，得到选衣用的保暖缺口；② 展示取暖维时乘 15 变成扣分（第 2.4 节）。所以跑步这类高强度会明显压低保暖需求。

旧版说明里的「引擎支持 9 种活动但界面只能选 8 种（开车选不到）」已修复：`SELECTABLE_ACTIVITIES` 与 `ACTIVITY` 现为 9 种一一对应，并有单测锁双向差集为空。

## 2. 逐步拆解：每个判定点与实测

### 2.1 作用温度（每个整点）

```
作用温度 = 气温 + 辐射增益 − 风寒 + 湿度负载
```

| 项 | 规则 | 阈值/系数 |
| --- | --- | --- |
| 辐射增益 | 只在 7–18 点算；= 辐射 W/m² × 0.006，**封顶 5℃** | 晴天 600 W/m² → +3.6℃ |
| 风寒 | 只在气温 ≤10℃ 且风速 ≥4.8 km/h 时算；标准风寒公式取"降温量" | 风 >10℃ 一律不计 |
| 湿度负载 | 只在气温 ≥26℃ 时算；每高出基准 40%RH 的 10% → +0.6℃ | 90%RH 时 +3.0℃ |
| 有效风 | 环境风速 + 活动自生风 | 骑行 +4.0 m/s |

要点：**湿度只在高温侧起作用**（低温时不看湿度，避免把"湿冷"误算成"更冷"），所以低温湿度差异不影响作用温度，只影响透气需求。

### 2.2 所需 clo 与设计时刻

```
所需 clo = (中性温度 − 作用温度) / 12      ≤0 记 0，**不封顶**
```

**每 1 clo 对应 12℃ 温差**（旧版是 6.5，会把 0℃ 静坐需求推到 3.4 clo，远超任何合理着装；改为 12 后 0℃ ≈ 1.8 clo、−10℃ ≈ 2.7 clo，与 ISO 9920 的组合热阻量级一致）。

设计时刻 = 全天所需 clo 最高的那一小时（实测里就是凌晨最低温那小时，如均温 −22℃ 那天是凌晨 3 点、−27℃）。**衣物清单由它决定**。

选衣用的保暖缺口 = 设计时刻所需 clo − 代谢抵消，同样不封顶：

| 均温（日内 ±5℃） | 设计时刻 | 设计时刻所需 clo | 选衣用缺口（扣代谢后） |
| --- | --- | --- | --- |
| −22℃ | 3 时 −27℃ | 4.77 | 4.47 |
| −16℃ | 3 时 −21℃ | 4.18 | 3.88 |
| −8℃ | 3 时 −13℃ | 3.38 | 3.08 |
| 0℃ | 3 时 −5℃ | 2.59 | 2.29 |
| 8℃ | 3 时 3℃ | 1.80 | 1.50 |
| 16℃ | 3 时 11℃ | 0.92 | 0.62 |
| 20℃ | 3 时 15℃ | 0.58 | 0.28 |

（此为 T1 行内实测读数；缺口从 −22℃ 到 20℃ 单调下降，低温侧不再有"所有天共用同一个数"的饱和。）

### 2.3 安全预警（先算，强制抬需求）

| 触发 | WATCH | DANGER | 强制需求 |
| --- | --- | --- | --- |
| 白天最高温 | ≥33℃ | ≥35℃ | DANGER：透气 ≥80、遮阳 ≥70、保暖 0；WATCH：遮阳 ≥40 |
| 凌晨最低温 | ≤−5℃ | ≤−10℃ | 保暖 ≥75 / ≥95 |
| 全天最大风 | ≥10 m/s | ≥15 m/s | 防风 ≥50 / ≥90 |
| 全天雨量 | ≥4 mm | ≥8 mm | 防雨 ≥60 / ≥95 |
| 老人/儿童 + 最高温 ≥33℃ | — | — | 透气 ≥60 |

实测：37℃ 晴天 → DANGER，需求 = 透100/晒80，衣物 速干背心+沙滩裤+防晒衣，配饰 墨镜/遮阳帽/防晒霜/备用贴身衣。

### 2.4 六维需求向量（各维取全天最坏）

| 维度 | 驱动量 | 0→100 的区间 | 修正 |
| --- | --- | --- | --- |
| 保暖 WARMTH | 全天最大所需 clo（展示用） | 0.4 → 2.0 | −代谢抵消×15 |
| 防风 WIND | 全天最大有效风（环境+自生） | 4 → 12 m/s | — |
| 防雨 RAIN | max(降水概率 30→85，雨量 0.5→4 mm/h) | — | ×雨暴露系数 ×暴露习惯（0.6/1/1.2）；**通勤窗口有雨再抬到 40**（见第 2.13 节） |
| 透气 BREATHABILITY | 作用温度 | 25 → 33℃ | 湿度>70% +15；MET≥3.5 至少 45 |
| 遮阳 SOLAR | UV 指数 | 3 → 8 | ×日晒暴露系数 ×人群日晒敏感 |
| 可脱卸 REMOVABLE | 昼夜温差 | 8 → 16℃ | — |

**展示维保暖有饱和点**：所需 clo ≥ 2.0（作用温度 ≤ −2℃ 附近）就显示 96 分上下。实测静风扫描（B3）：−22℃ 到 0℃ 的展示保暖都顶在 96，6℃ 降到 80、8℃ 降到 70，**但这不再意味着同一套衣服**——选衣读的是第 2.2 节那张不封顶缺口表：−22℃ 缺 4.47 clo（库都不够，报 insufficient）、0℃ 缺 2.29、6℃ 缺 1.70，实测组合与覆盖判定逐档不同（第 4.1 节）。展示维的饱和只影响数字观感，不影响任何选衣决策。

### 2.6 每槽候选怎么挑（准入 + 拟合评分）

先按 `层角色 + 品类` 分池（保暖槽在严寒时并入厚外套），再硬过滤：

1. **clo ≥ 槽位下限**；
2. 要求防水则 `water ≥ 0.85`；要求防风则 `wind ≥ 0.6`；要求遮阳则 `solar ≥ 0.8`；
3. **反季准入**：设计时刻超出这件衣服的舒适窗 **±6℃** 即淘汰（"季节不对"不是"差一点"）。**防护层槽豁免**——雨衣/防风壳在盛夏深冬都要可达。

过滤后按拟合分排序取 **前 6 件**，再补 **最厚的 2 件合格件**（贴合排序天然偏好"差值最小"，厚度选项必须留在桌上给联合评分）：

| 项 | 公式 | 说明 |
| --- | --- | --- |
| 保暖层就近 | `30 − min(30, |clo − (槽下限+0.1)| × 40)` | 越接近目标越高分 |
| 贴身层透气 | `透气 × 20 × (0.4 + 透气需求/100 × 0.6)` | 冷季权重 0.4，热季 1.0 |
| 贴身层目标 clo | 上装 `0.05 + 缺口刻度×0.3`；下装 `0.04 + 缺口刻度×0.26`，再 ×(0.6+缺口刻度) | 缺口刻度 = min(1, 缺口/3.0)；贴身只承担一小份保暖 |
| 防护层侧重 | 防水壳 `water×30`、防风壳 `wind×25`、遮阳 `solar×35`，另加 `透气×10` | 按槽位要求叠加 |
| 轻量 | `(1 − 克重/1500) × 15` | 越轻越好 |
| 可脱卸 | `可脱卸需求 × 0.15`（仅可脱单品） | 温差大时偏外套 |
| 舒适窗 | 盖得住设计时刻 ±2℃ 时 +5 | — |
| 偏好加成（第四步） | 风格命中 +6 / 呈现命中 +4 / 版型命中 +3 / 色彩命中 +3 | 仅显式设置时生效；让合适件进得了前 6 池，默认设置下无加分 |

**合格池为空时的兜底**：退回该角色+品类的原始池，按"离设计时刻最近的件"排序取前 6——让极寒场景兜底的是最接近的一件（发热保暖裤），而不是拟合分恰好高的裙装或短打。这条有回归测试（S2-5：−24℃ 下 BASE/BOTTOM 候选首位是全库离设计时刻最近的件）。

### 2.7 组装：整套联合搜索（beam）

不再"逐槽取第一名然后祈祷"。组装是**在所有槽位的候选组合上做 beam 搜索**，每个中间组合按整卷得分剪枝，保留前 32 条路径（beamWidth=32），最后一卷的得分即最终分。同一件衣服不会在一套里出现两次。

每一步的硬条件检查（`slotHardSatisfied`，比准入更严）：`water ≥ 0.9`（防水槽）、`wind ≥ 0.7`（防风槽）、`solar ≥ 0.8`（遮阳槽）、`clo ≥ 槽下限`、**且过反季准入**。某个槽位没有任何候选过得了硬条件时：

- 保留"尽力而为"的一件给界面展示，但整卷登记 `RELAXED_<角色>`；
- 候选池为空则登记 `NO_CANDIDATE_<角色>_<品类>`，不产生凭空衣物；
- 覆盖判定读到任何 relaxed 就直接判 `insufficient`，**不把不合格的组装冒充合格推荐**（第 2.12 节）。

为什么值得用联合搜索：有的场景里"上装补齐了、下装仍在过薄处打转"的逐槽贪心解会被整卷比较淘汰。实测（S2-6 的三个判别场景）beam=32 得分严格高于 beam=1 的贪心：6℃ 近似 68.6>65.3、−8℃ 近似 69.6>64.0、雨天近似 76.4>76.2。

**搜索质量的实测上界**（T10，与穷举 DFS 对比）：产品场景里 6℃ 与 −20℃ 两例 beam 与穷举**完全相同**（68.6=68.6、68.1=68.1），构造的雨天场景 beam 76.4 vs 穷举 78.5（差 2.1 分，约 2.7%）。beam 不是严格最优，验证句只锁"显著优于贪心"的关系，不锁"等于最优"；已知反例与量化代价见第 5.2 节遗留 3。

### 2.8 有效 clo（叠穿不等于相加）

- **打折按"角色"发生**：同一角色里排第二的那件只算 `clo × 0.85`。贴身下装与贴身上装同属 BASE 角色，所以第二条 BASE 同样被打折——这是保守估计（上下装实际是并排覆盖），代码注释与实现现已一致。
- **外层风挡 < 0.8 → 整套再乘 0.85**（风穿透）；**没有外层时同样吃这个 0.85**，即"不穿壳"在数值上被视为漏风。

实测 −22℃ 那套（发热保暖内衣 0.36 + 发热保暖裤 0.32 + 棉服 1.0 + 羽绒服 1.2 + 派克服 1.15）：名义 `0.36 + 0.32×0.85 + 1.0 + 1.2×0.85 + 1.15 = 3.80`，外层派克服风挡 0.75 < 0.8 再 ×0.85 → **有效 3.23 clo**。

### 2.9 评分（匹配度分，不是"穿得对不对"）

第四步起改为**分项满分制**（方案 §7.3）：保暖 25 / 天气防护 20 / 活动舒适 15 / 风格场合 18 / 整套协调 10 / 可脱卸 5 / 用户偏好 4，**合计 97**（剩余 3 分的"多样性"与滞回一起排第五步）。`dayScore` = 七项之和（0–100），`scoreBreakdown` 输出逐项得分给界面分数卡。硬过滤与安全判定不读分数——分数只决定"合格候选里谁排前面"。

| 分项 | 满分 | 怎么算 |
| --- | --- | --- |
| 保暖 | 25 | `缺口 = requiredClo（含反馈偏置）− 有效clo`；欠保暖每 1 clo 扣 22.5 分（穿少了会冷，罚得重）；略微过暖每 1 clo 扣 6.25 分、**封顶 7.5 分**（穿多了只是沉） |
| 天气防护 | 20 | 风/水/晒属性按需求加权（权重 = 该维需求/100 + 0.15 基准）后归一——零需求也不把属性一票否决 |
| 活动舒适 | 15 | 透气 70% + 轻量 30%；透气权重 = 0.4 + 0.6 ×（透气需求/100 + 闷反馈偏置）；重量预算 2500g 线性衰减 |
| 风格场合 | 18 | 只统计用户显式设置的子项：风格多选（权重 0.55）与穿着场合正式度（权重 0.45 + 不符合场合反馈偏置）；未设置取中性 0.8 档 = 14.4 分，不产生排序信号 |
| 整套协调 | 10 | 设计时刻低于 12℃ 起折算下装应承担的保暖分额 `(12 − 设计时刻) × 0.03 clo`（上限 0.32 clo，约一件加绒长裤），下装不足每缺 1 clo 扣 6 分；整套 ≥3 个非中性色组再扣 2 分（S2-4 验证：0℃ 薄下装组严格更低分，24℃ 两组相等） |
| 可脱卸 | 5 | 可脱件数 2 件即取满（温差场景够用） |
| 用户偏好 | 4 | 色彩 0.4 / 版型 0.3 / 呈现 0.3 三个子项各自命中率加权；未设置取中性 0.8 档 = 3.2 分，不产生排序信号 |

**反馈闭环**（方案 §6.1）：每条反馈只小步调整、有上限、可撤销——"太冷/太热"每步改保暖目标 ±0.1 clo（帽 ±0.3），"闷"每步抬透气权重 0.1（帽 0.3），"不符合场合"每步加大正式度权重 0.1（帽 0.3），"正合适"只记录不改分；撤销 = 删最后一条（`revokeLastFeedback`）。反馈不动安全阈值与天气事实。

**分数分布实测**（T1 阶梯）：−22℃ 缺 1.24 clo → 40.1 分（扫到的最低）；0℃ → 69.5；8℃ → 67.7；30~32℃ → 83.1（最高）。极寒低分现在表达的是"缺口真实存在"，不再是旧版"目标固定 1.0 clo"的口径副作用。但**它依然只是匹配度，不是安全等级、也不是推荐可信度**——够不够穿由覆盖判定（第 2.12 节）与安全等级分别回答。

### 2.10 此刻穿哪几层

| 层 | 规则 |
| --- | --- |
| 贴身层 | 始终穿着 |
| 保暖层 | 当前作用温度 ≤ 该层首件舒适上界 + 3℃ 时穿着，否则脱下 |
| 防护层 | 当前小时在下雨（全天雨量>0.3 且该小时雨强>0）或 当前作用温度 ≤12℃ 时穿着 |

实测三条整日时间线（T8 逐时穿着 + T8e 时间线事件；字母：B 贴身 / I 保暖 / P 防护，数字为整点区间）：

- **秋日昼夜 6~24℃（均温 15）**：0–7 时 `BI`，8–22 时只剩 `B`（白天升温脱掉中层），23 时回到 `BI`。时间线事件：15 时 `REMOVE 轻薄羽绒服`、19 时 `ADD 轻薄羽绒服`——事件标 15 时脱、19 时回，逐时穿着实际是 8 时脱、23 时回，**两处都对不上**（第 5.2 节遗留 5）。
- **春雨 5~14℃、8 点与 18 点有雨**：0–9 时 `BIP`，10–17 时 `BI`（中午脱的是外壳，中层仍穿），18–23 时回到 `BIP`（傍晚雨+降温）。事件：15 时 `REMOVE 抓绒衣`、17 时 `ADD 硬壳冲锋衣`、21 时 `ADD 抓绒衣`——实际中层全天没脱、外壳是 10 时脱/18 时回，**三处全对不上**（遗留 5）。
- **冬晴 −6~4℃**：全天 0–23 时 `BIP`——防护层那件是严寒外壳（派克服），中午最高作用温度 4℃ 仍 ≤12℃ 穿着阈值，全天不脱。事件：15 时 `REMOVE 充绒马甲`、21 时 `ADD 充绒马甲`——实际全天穿着从未脱下，**也对不上**（遗留 5）。

### 2.12 覆盖判定 coverage（衣物库够不够用）

输出字段：`status / requiredClo / availableClo / capacityClo / deficitClo / catalogDeficitClo / confidence / unmetNeeds`。判据读的需求含反馈保暖偏置（"太冷"反馈会同步抬高 `requiredClo`，覆盖口径不脱节）。四态判据（按序）：

| 判定 | 条件 | 含义 |
| --- | --- | --- |
| `insufficient` | 有槽位被放宽（RELAXED_*）；或 库容量缺口 > min(0.4 clo, 需求×0.4) | 不是"差一点"，是这套/这库真的不够 |
| `unknown` | 无逐时预报（且未被上面捕获） | 数据不够，不敢下结论；置信度 0.4 |
| `marginal` | 这套比需求薄 > 0.05 clo；或 需求 ≥0.3 且余量 < 0.2 clo | 勉强够，没有余量 |
| `adequate` | 其余 | 够用 |

`capacityClo` 是"同样槽位结构下，库里最多能凑到多少"（每槽贪心取最厚、不重复用件）——它把"这套偏薄（deficitClo）"与"库里根本没有（catalogDeficitClo）"分开，两者对用户的说法不同。

实测覆盖带（T1 行内读数，日内 ±5℃）：**−10℃ 及以下 insufficient**（−14℃ 起出现容量缺口 CATALOG_INSUFFICIENT，−22℃ 达 1.91 clo；−10/−12 是纯"槽位被放宽"）；−8℃ 到 +2℃ marginal；4℃ adequate；6~18℃ marginal（"刚好够"带）；20℃ 以上 adequate。

其中 −10℃ 档的 insufficient 值得知道细节：它是**贴身下装槽没有任何一件过得了反季容差**（发热保暖裤舒适窗下界 −8℃，离设计时刻 −15℃ 超过 6℃ 容差）触发的 `RELAXED_BASE`，而不是库容量差——系统按预案如实报"hard 条件没满足"，没有拿不合格组装冒充合格。这是当前目录数据与容差参数的真实边界（第 5.2 节遗留 2）。

### 2.13 雨具两件事：rainPlan（穿与带分开、同源）

`rainPlan` 把"带不带"与"穿不穿"分开给结论，但两条判定读同一组通勤暴露事实（`exposure.ts` 是唯一来源）：

| 字段 | 含义 |
| --- | --- |
| `facts.commuteMaxLegChance / commuteMaxLegMmPerHour / dayRainMm / windMaxInCommuteMs` | 通勤窗口内最大降水概率 / 最大雨强 / 全天雨量 / 窗口内风速峰值 |
| `carry` | 携带结论（= umbrella.verdict，SKIP/BRING/RAINCOAT） |
| `wearShell` | 是否真的需要穿防水外壳/雨衣 |

判定线：窗口内"最大整点概率 ≥ 40%"或"最大雨强 ≥ 0.5 mm/h"或"全天雨量 ≥ 4 mm"记 wetInWindow；`wearShell = 带伞结论不是 SKIP 且 wetInWindow`。**不带伞的日子也不要求穿防水壳**——两条结论不会互相打脸。

配套修复：防雨需求有一条**通勤下限**——窗口内最大整点概率 ≥40% 时，防雨需求抬到至少 40（0-100 刻度）。"室内办公"只把雨暴露权重降为 0，不等于不经过户外。实测（T3b）：14℃、概率 70%、雨强 0.8 mm/h（全天 1.6 mm）时，**办公与步行都会给出防水外层**（硬壳冲锋衣）；旧版办公在这种天不给壳、而带伞判定照样让人带伞的矛盾已消除。

- **防水一列全部是 40%**：这是"通勤窗口概率 ≥40% → 防雨需求抬到 40 → 壳槽"的下限线统一作用，任何活动（含室内）只要窗口里有雨都会拿到防水外层。旧版"室内永不触发、只有雨量 ≥4mm 才有例外"的断档已不存在。

| 没有逐时预报 | 按当日最低/最高温 + 日出日落合成昼夜曲线（第三步起，替换原固定 ±6℃）；实测三档温度下衣物与有逐时**完全一致**，覆盖判定转为 `unknown`、置信度 0.4（真实数据下曲线形态接近但不保证逐点相同）；**不会把估算声称成实测精度** |
| 某整点降水概率缺失（内部 −1） | 该整点不作为暴露窗口样本（不产生负概率、也不吞掉另一段的有效信号，有单测）；穿衣防雨维仍读全天概率与雨量 |
| 湿度缺失（−1） | 不加载湿度负载；贴身层透气权重下降 |
| 无云量/辐射数据 | 辐射走估算（白天正弦峰值 800 W/m²，按云量衰减；云量未知按 0.7 系数） |
| 未设通勤时刻 | 穿衣清单不受影响；暴露窗口与带伞用兜底 07:30/18:00，并标记 assumed |

实测对照（均温 10 / 2 / 16℃ 三档，第四步后重跑）：每档无逐时与有逐时**给出同一套衣物**（10℃：`纯棉T恤+厚裙 ｜ 棉服+针织开衫`，有效 clo 1.44；2℃：`长袖棉衫+发热保暖裤 ｜ 充绒马甲+针织开衫 ｜ 派克服`，2.24；16℃：`运动速干T恤+紧身裤 ｜ 保暖马甲`，0.64）；差别只在状态与置信度——有逐时 `marginal`/1.0，无逐时 `unknown`/0.4。第三条：精度声明与衣物建议分离，估算不冒充实测。

### 4.8 服装库实际可达性（65,610 个场景网格统计，T7）

网格：均温 −20~38℃（步进 2，日内 ±5℃）× 降水概率 {0,50,80}% × 环境风 {2,8,16} m/s × UV {2,6,10} × 9 种活动 × 3 人群 × 3 体质 = **65,610 次 `plan()`**。

结果：**45 件里 36 件出现过（旧版 17/45；第二步审计后 30，第四步后 36），9 件一次都没被选中**。被选中次数最多的 8 件：硬壳冲锋衣 37,633、发热保暖裤 32,419、发热保暖内衣 23,332、轻薄羽绒服 21,153、速干背心 21,023、沙滩裤 17,294、防水冲锋衣 16,573、针织开衫 15,024。

从未出现的 9 件：

| 层 | 从未被选中的衣物 |
| --- | --- |
| 贴身上装 | 短袖T恤 |
| 贴身下装 | 牛仔裤、工装裤 |
| 保暖层 | 羊毛毛衣 |
| 防护层 | **雨衣、轻便雨披**、风衣、复古厚夹克、亚麻西装外套 |

三点解释（都有实测支撑）：

- **日常裤装只剩最后一档没打开**：牛仔裤/工装裤仍不可达，但薄休闲裤、紧身裤、羊毛裤、阔腿裤第四步后都已入选（居家场景首次给出羊毛裤）；剩余两件在"贴身层目标 clo"上总和更优解差一点点。这是后续目录/权重校准要继续处理的集中度问题（旧版 28 件从未出现 → 第二步 15 → 第四步 9）。
- **雨衣/雨披仍被硬壳压制**：防风槽与防水槽的整卷评分里，硬壳/防水冲锋衣的风挡 1.0 与轻量综合领先；雨衣（风 0.80、透气 0.10）与雨披（风 0.50、透气 0.05）全面落后。带伞判定给 RAINCOAT（"用雨衣"）时，穿衣侧实际给的是**硬壳冲锋衣**——功能上是同类防水外壳，但单品名不同，界面文案要按实际推荐件说（第 5.2 节遗留 4）。
- **"从未出现"依赖输入网格**：这是"常用输入 + 默认偏好"网格里的统计；件与件之间的差距常常只有零点几分（如 短袖T恤 与 运动速干T恤 的透气只差 0.05），换一组网格或更改偏好就可能翻盘——它说明推荐集中在少数几件，不是这 9 件永久不可用。

### 5.2 遗留（正文前向引用的编号在此兑现）

1. **防风壳槽的默认件偏防水**：整卷评分里防水项带 0.15 基准权重、与需求无关地入账；B1 重扫里 9 个活动的**首个防风外层全部是硬壳冲锋衣**（触发分界附近防风夹克仍竞争不过），纯风天大温差场景经整卷比较已改给派克服（T6w，69 分）。功能不出错（硬壳必然防风），但单品选择偏防水。处理：权重校准阶段把 water 项条件化（仅当 RAIN 需求显著时计分），排方案第五步。
2. **≤−10℃ 的 insufficient 由 `RELAXED_BASE` 触发**：发热保暖裤舒适窗下界 −8℃、设计时刻 −15℃，超出 ±6℃ 容差 → 贴身下装槽没有一件过得了硬条件（−10/−12 为纯放宽，库容量无缺口）；−14℃ 起还会叠加 `CATALOG_INSUFFICIENT`（−22℃ 达 1.91 clo，容量真不够）。这是目录数据与容差参数的真实边界，系统如实上报、不伪装（T1 行内实测）。处理：下装舒适窗扩数据或容差按槽位差异化，排第五步。
3. **beam 近似代价**：宽度 32。T10 实测 6℃ 与 −20℃ 两场景 beam 与穷举同分（68.6=68.6、68.1=68.1），构造雨天场景 76.4 vs 穷举 78.5（差 2.1 分，约 2.7%）；且存在现实反例——北方寒潮场景（T3 首行）产品配置给出 53.0 分/有效 2.30 clo 的组合，把 beam 放宽到 20,000（覆盖全部 3,072 条候选路径）后给出 58.5 分/3.79 clo 的厚外套组合（全枚举复核 A5）。即中间剪枝确实剪掉过更优路径；两侧覆盖判定都报 insufficient，不会把不足冒充够，但组装的单品选择与保暖厚度吃了亏。处理：目录或候选池变大时复核宽度，排第五步。
4. **雨衣 / 雨披不可达 + RAINCOAT 文案不一致**：带伞判定给 RAINCOAT（"用雨衣"）时，穿衣侧实际给硬壳冲锋衣（T3 夏日暴雨、海风两行）——同类防水外壳但单品名不同。处理：UI 文案按实际推荐件渲染（UI 轨）；雨具单品是否拉回候选（算法权重）排第五步。
5. **timeline 与逐时穿着两条通道判据未统一**：三个场景全部对不上——秋日昼夜：事件 15 时 REMOVE / 19 时 ADD 轻薄羽绒服，逐时穿着实际 8 时脱、23 时回；春雨：事件 15 时 REMOVE 抓绒衣 / 17 时 ADD 硬壳冲锋衣 / 21 时 ADD 抓绒衣，实际中层全天没脱、外壳 10 时脱、18 时回；冬晴：事件 15 时 REMOVE / 21 时 ADD 充绒马甲，实际全天穿着未脱。处理：以逐时穿着为准生成事件（或两处共用一个穿脱时刻判据），排第五步。
6. **滞回 / 换装惩罚未实现**：逐时穿着在阈值附近没有迟滞，加脱层没有次数代价。方案第五步（与"少换装"权重一起做）。
7. **遮阳需求 UV≥8 饱和**：`normalize(uv, 3, 8)`，UV 8 以上无区分度（T6 的 uv 触发区间 5.1~7.1 贴着该线）。处理：开放（更高 UV 是否要更强防护与更细区间）。
